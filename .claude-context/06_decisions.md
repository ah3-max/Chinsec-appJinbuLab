# 06_decisions.md — 技術與業務決策記錄

> 此檔記錄所有重要決策的「為何」。當未來有人想改某個設計時，先看這裡。
> 採用 ADR (Architecture Decision Record) 格式。

---

## ADR 結構說明

每筆決策包含：
- **狀態**：已採用 / 已棄用 / 已替換
- **背景**：當時為何要做這個決策
- **選項**：考慮過哪些方案
- **選擇**：最後選了什麼
- **理由**：為何選這個
- **後果**：這個選擇的影響（好的、壞的）

---

## ADR-001：選擇 Next.js 全端而非分離式架構

**日期**：2026-04-26
**狀態**：✅ 已採用

**背景**：要快速做出一個學習平台 MVP，順元時間有限。

**選項**：
- A) Next.js 全端（前端 + API routes）
- B) Vue/Nuxt 全端
- C) React + 獨立 FastAPI / NestJS 後端
- D) Django Full-stack

**選擇**：**A) Next.js 全端**

**理由**：
1. 與順元另一專案 ComfortPlus ERP 同架構，未來可合併
2. 單一語言（TypeScript）減少維護成本
3. App Router 對 i18n、Server Components 支援好
4. Vercel / Docker 雙部署都靈活

**後果**：
- ✅ 開發速度快
- ✅ 部署簡單
- ⚠️ 重 CPU 工作（影像處理）需另開 worker
- ⚠️ Server Component vs Client Component 邊界要小心

## ADR-002：選擇 PostgreSQL + Prisma 而非 MongoDB / Drizzle

**日期**：2026-04-26
**狀態**：✅ 已採用

**選項**：
- A) PostgreSQL + Prisma
- B) PostgreSQL + Drizzle
- C) MongoDB + Mongoose
- D) MySQL + Prisma

**選擇**：**A) PostgreSQL + Prisma**

**理由**：
1. Prisma multi-file schema 支援 → 模組化（auth/curriculum/exercise...）
2. PostgreSQL JSON 型別 + enum + 全文搜尋（題目選項用 JSON、等級用 enum）
3. 與 ComfortPlus 同（順元已熟悉）
4. Prisma Studio 視覺化好用，順元可直接看資料

**後果**：
- ✅ 強型別資料模型
- ✅ Migration 自動產生
- ⚠️ Prisma 在大量寫入時不如 Drizzle 快（但學習平台不需要）
- ⚠️ 多檔 schema 要注意 preview feature 設定（已踩過坑）

## ADR-003：AI 路由策略（內網優先 + 雲端備援）

**日期**：2026-04-26
**狀態**：✅ 已採用

**背景**：學員資料敏感（語音、手寫），且大量呼叫 Claude API 成本高。

**選項**：
- A) 全用 Claude API
- B) 全用本地 LLM（LM Studio + Ollama）
- C) 混合：本地優先 + Claude 備援
- D) 由用戶選

**選擇**：**C) 混合策略**

**理由**：
1. 內網優先保護學員隱私
2. 簡單任務（對話練習）本地夠用，省 99% 成本
3. 複雜任務（作文批改）Claude 品質明顯較好
4. Fallback 機制保證可用性

**任務分流**（詳見 `02_architecture.md`）

**後果**：
- ✅ 成本可控（預估 < NT$ 200 / 員工 / 月）
- ✅ 隱私好
- ⚠️ 部署複雜（要管 LM Studio + Ollama + Claude 三套）
- ⚠️ 內網斷線時 Claude API 會被當備援湧入

## ADR-004：選擇線性升級而非 Track 並行

**日期**：2026-04-27
**狀態**：✅ 已採用（順元決定）

**背景**：學員有 4 種 Persona（照服員、行政、廚房、語言中心生），中文程度差異大。

**選項**：
- A) 純線性：注音 → A1 → A2 → ...
- B) 雙軸並行：主軸（語言）+ 支軸（情境）
- C) 三軸並行：語言 + 情境 + 考試
- D) 多 Track：5 條獨立路線
- E) Claude 建議的混合

**選擇**：**A) 純線性升級**（順元堅持）

**理由（順元的考量）**：
1. 簡單明確，員工不會迷惑
2. 每個 Level Boss 通關 → 績效獎金事件，獎金鏈條乾淨
3. 課程開發只需做一條主線，集中資源
4. 線性適合內部認證（你完成 X，發給你 Y 證書）

**Claude 的補充設計**：
- 雖然線性，但**每個 Level 內含 12 個情境關卡**
- 讓「線性」在巨觀上單純，「微觀」上豐富

**後果**：
- ✅ 商業邏輯清楚
- ✅ 開發焦點集中
- ⚠️ 已是 B1 程度的學員會覺得從頭學注音浪費時間 → 用 Placement Test 解決
- ⚠️ 不同 Persona 用同一條路線，需要靠情境關卡多元化吸引

## ADR-005：12 個情境全部養老院相關

**日期**：2026-04-27
**狀態**：✅ 已採用（順元決定）

**背景**：每個 Level 12 個情境，是要全部養老院還是混合？

**選項**：
- A) 12 個全養老院
- B) 8 養老院 + 4 辦公室/廚房
- C) 6 養老院 + 6 通用生活
- D) 學員選

**選擇**：**A) 12 全養老院**

**理由（順元的考量）**：
1. 主要學員是住院照服員（60%）
2. 廚房清潔人員的核心需求其實也是「跟阿公阿嬤、同事溝通」
3. 辦公室行政另外有商用詞彙包，不必擠進主軸
4. 集中資源做深做精

**Claude 的補充**：
- 雖然全養老院，但會涵蓋：飲食、清潔、藥物、緊急、文書等多面向
- 行政人員可進入「行政相關情境」（如 L4-S07 寫照護計畫）
- 廚房人員實際需要的「跟阿嬤說我幫您打飯」也在 L1-S08 飲食詞彙

**後果**：
- ✅ 內容深度足
- ✅ 與績效獎金邏輯一致（學養老院技能 → 阿公阿嬤滿意 → 獎金）
- ⚠️ 廚房 / 行政員工會覺得不夠貼切 → 未來補「職務情境包」

## ADR-006：漸進式介面語言（4 階段）

**日期**：2026-04-27
**狀態**：✅ 已採用（順元決定）

**選項**：
- A) 始終母語對照
- B) 始終全中文
- C) 漸進：母語 → 雙語 → 中文
- D) 學員自選

**選擇**：**C) 漸進式**

**理由**：
1. 初期母語降低恐懼門檻
2. 中期雙語確保學會
3. 後期沉浸強化記憶
4. 沒選 D 是因為「自選」會選最舒服的（始終母語），無法進步

**實作**：
```typescript
function getUiLanguageMode(level: Level) {
  if (level === 'ZHUYIN') return 'NATIVE';
  if (level === 'A1_BEGINNER') return 'NATIVE_FIRST';
  if (level <= 'B1_INTERMEDIATE') return 'BILINGUAL';
  return 'IMMERSION';
}
```

**後果**：
- ✅ 心理上易接受
- ✅ 教學效果好（語言學家證實漸進式優於沉浸式）
- ⚠️ 介面元件要支援多種顯示模式 → 增加開發複雜度
- ⚠️ 未來客製化（如「我想提早全中文」）要再設計

## ADR-007：對標內部認證而非 TOCFL

**日期**：2026-04-27
**狀態**：✅ 已採用（順元決定）

**選項**：
- A) TOCFL 國家考試
- B) 新住民華語考試
- C) 內部認證 + 績效獎金
- D) 多軌：A + B + C 都做

**選擇**：**C) 內部認證 + 績效獎金**

1. 員工不一定願意花錢去考國家考試

4. 由愛愛院發證書，符合營運需求

**後果**：
- ✅ 商業邏輯閉環
- ✅ 員工動機強
- ⚠️ 認證的「外部公信力」較弱 → 預留未來升級空間
- ⚠️ 證書設計、QR 驗證要做好（防偽）

## ADR-008：採用方案 C（CLAUDE.md + 子檔分層 + 自動腳本）

**日期**：2026-04-27
**狀態**：✅ 已採用（順元決定）

**背景**：Claude Code 每次啟動 context 是空的，需要長期記憶系統。

## ADR-010：UserAttempt 改為 exerciseId 可選

**日期**：2026-04-27
**狀態**：🔄 進行中（P0-3）

**背景**：注音題型動態產生（前端 random 出題），不對應 DB Exercise 紀錄。

**選項**：
- A) 為每個動態題目都建 Exercise 紀錄
- B) UserAttempt 不存題目細節
- C) UserAttempt.exerciseId 改 optional + 加 exerciseSnapshot 欄位
- D) 改用 NoSQL 存題目

**選擇**：**C)**

**理由**：
1. A 會爆量（每個學員每題都建一筆 Exercise）
2. B 失去答題分析能力
3. C 平衡：有 Exercise 就連，沒有就存快照
4. D 為此改技術棧太誇張

## ADR-011：Edge-TTS 而非 Azure / Google / OpenAI TTS

**日期**：2026-04-26
**狀態**：✅ 已採用（部分實作中）

**選項**：
- A) Microsoft Edge TTS（CLI 免費版）
- B) Azure Speech Service（付費）
- C) Google Cloud TTS（付費）
- D) OpenAI TTS API（付費）
- E) 本地 Coqui TTS / VITS

**選擇**：**A) Edge TTS**

- ⚠️ 不是公開 API，未來可能被限制（已用 1 年穩定）
- ⚠️ 預生成需要時間 + 儲存空間（200+ 檔約 50 MB）

## ADR-013：超級管理員一鍵 Impersonation

**日期**：2026-04-27
**狀態**：🔄 進行中（P0-1）

**背景**：順元需要日常測試多語介面，每次手動切帳號太煩。

**選項**：
- A) 不做，每次手切
- B) 切換 cookie 的工具（瀏覽器擴充）
- C) 內建 Impersonation 機制
- D) 開發環境繞過密碼

**選擇**：**C) 內建 Impersonation**

**理由**：
1. 業界標準做法（Atlassian、GitLab 都有）

- 模擬期間禁敏感操作（改密、刪帳、HR）
- 全程寫 AuditLog

## ADR-014：選擇 Cloudflare Tunnel 而非開 Port

**日期**：2026-04-26
**狀態**：✅ 已採用

**背景**：愛愛院內網要對外提供服務，傳統做法是 NAT + 防火牆開 port。

**選項**：
- A) 開 port（傳統方式）
- B) Cloudflare Tunnel（不開 port）

- ⚠️ 依賴 Cloudflare 服務
